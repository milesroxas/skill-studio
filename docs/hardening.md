# Hardening checklist

Known issues in the product's logic and workflow, from a QA review on 2026-11-06, checked against the code on 2026-11-11. The [Jev](#jev) section is from a review of every question the app asks Jev, on 2026-11-13 at `b1e0b1d`, against the TypeSafe docs of that day. Each line is one issue: its id, its severity, what is wrong, and where. A Jev line also says what fixes it. Paths with line numbers are as of `ee7ae14`; a path with none names a file as it is now.

## How to use this file

- `[ ]` is open. `[x]` is fixed on `main`: add the commit after the line.
- An issue that turns out not to hold: tick it and add "not a bug" with the reason.
- A fix people will notice also needs a line in [CHANGELOG.md](../CHANGELOG.md).
- When every line is ticked, delete this file.

Severity: **high** gives wrong scores or loses data. **med** misleads or breaks a step. **low** is an edge case or friction.

## Fix order

1. R1, R2, R3: scores graded against the right case, skill and rules.
2. R4, R5, R6: a failed sample counts as a failure.
3. C1, C2, C3: runs compared only when they are like for like.
4. J4: a rule or check that states pixels is measured, not looked at.
